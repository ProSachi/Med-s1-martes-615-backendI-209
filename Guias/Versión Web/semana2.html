Colecciones en Java

Son una estructura de datos dentro del paquete java.util diseñada para almacenar, manipular y agrupar objetos como una sola unidad.

Proporcionan una alternativa dinámica y más flexible a los arrays, permitiendo añadir, eliminar, ordenar y buscar elementos eficientemente.

Las principales interfaces son List (ordenada, admite duplicados), Set (elementos únicos) y Map (pares clave-valor).

List (ArrayList)

¿Por qué no usar Arrays simples?

En lógica de programación tradicional, los arreglos tienen un tamaño fijo definido en tiempo de compilación.

En Java, si declaras int[] numeros = new int[5]; no puedes agregar un sexto elemento.

El ArrayList es una implementación de la interfaz List que utiliza un arreglo interno que se redimensiona automáticamente.

¡Crece un 50% de su capacidad cada vez que se llena!

Conceptos Clave

1

Tipos Genéricos (Generics)

Java utiliza <T> para definir qué tipo de objeto guardará la lista. Esto garantiza seguridad de tipos.

2

Wrapper Classes (Clases Envolventes)

Las colecciones NO pueden guardar primitivos (int, double, char). Deben usar sus versiones de objeto: Integer, Double, Character.

3

Índices

Al igual que en la lógica básica, el primer elemento es el 0.

4

Memoria

Un ArrayList mantiene el orden de inserción y permite elementos duplicados.

Clases Envolventes (Wrapper Class)

Una clase envolvente (wrapper class) "envuelve" un tipo de dato primitivo dentro de un objeto, lo que permite que pueda usarse en contextos donde se requieren objetos.

Cada tipo primitivo tiene una clase equivalente que permite tratarlo como objeto.

Primitivo → Clase Envolvente

int → Integer
double → Double
boolean → Boolean
char → Character

¿Para qué sirven?

  • Guardar datos en estructuras como ArrayList
  • Trabajar con valores null
  • Usar métodos útiles como parseInt(), toString(), compareTo(), etc.
  • Convertir valores primitivos a objetos
  • Convertir Strings a números

Autoboxing y Unboxing

Autoboxing: Java convierte automáticamente de primitivo a objeto.
Unboxing: Java convierte automáticamente de objeto a primitivo. 

int numero = 5;                  // tipo primitivo
Integer numeroObjeto = numero;   // autoboxing: se convierte automáticamente
int otroNumero = numeroObjeto;   // unboxing: de objeto a primitivo

Casteo (Casting)

Convertir entre tipos compatibles

Implícito:

int a = 10; 	
double b = a;

Explícito:

double x = 5.7;
int y = (int) x;  // y = 5

Parseo

Conversión de texto a otro tipo de dato usando wrappers

Anatomía y Operaciones Básicas - List (ArrayList)

Operaciones Fundamentales

  • add(E e) Añade al final de la lista
  • add(int index, E e) Inserta en una posición específica desplazando el resto
  • get(int index) Recupera el valor sin borrar
  • set(int index, E e) Reemplaza el valor en una posición
  • remove(int index) Elimina el elemento en la posición indicada
  • remove(Object o) Elimina la primera ocurrencia del objeto

Demo Paso a Paso: Gestión de Inventario Físico 

import java.util.ArrayList; // Necesario para usar la clase
import java.util.List;      // Recomendado instanciar desde la interfaz

public class GestionInventario {
    public static void main(String[] args) {
        // 1. Declaración e Instanciación
        // Usamos List (interfaz) a la izquierda y ArrayList a la derecha
        List<String> productos = new ArrayList<>();

        // 2. Operación: Escritura (Create)
        productos.add("Laptop");
        productos.add("Mouse");
        productos.add("Teclado");

        // 3. Operación: Lectura (Read)
        System.out.println("Primer producto: " + productos.get(0));

        // 4. Operación: Actualización (Update)
        // Cambiamos 'Mouse' por 'Mouse Inalámbrico' en el índice 1
        productos.set(1, "Mouse Inalámbrico");

        // 5. Operación: Eliminación (Delete)
        productos.remove("Teclado"); // Por objeto

        // 6. Recorrido (Iteración)
        System.out.println("--- Inventario Actual ---");
        for (String p : productos) {
            System.out.println("Producto: " + p);
        }
        
        // Pormenor: Tamaño de la lista
        System.out.println("Total productos: " + productos.size());
    }
}

💡 Concepto Clave:

Usamos List (interfaz) en la declaración y ArrayList en la instanciación. Esto sigue el principio de programar hacia interfaces, no hacia implementaciones concretas.

Estructuras Clave-Valor - Map (HashMap)

A diferencia de una lista donde para buscar un dato podrías tener que recorrerla toda (O(n)), un HashMap usa una función Hash para calcular la posición exacta. Es ideal para cuando tienes un identificador único (ID, Cédula, SKU) y quieres obtener un registro sin iterar.

Conceptos Clave

  • 1. Par K-V: La Key (llave) debe ser única. Si intentas insertar una llave existente, el valor se sobrescribe. El Value puede repetirse.
  • 2. Nullability: HashMap permite una llave nula y múltiples valores nulos.
  • 3. No hay orden: A diferencia del ArrayList, no garantiza que los elementos salgan en el mismo orden.
  • 4. Memoria: Consume más memoria que una lista porque guarda la relación y el valor del hash.
  • 5. Sobrescritura: Si se inserta una llave existente, el valor anterior se pierde y se reemplaza por el nuevo.

Casos de Uso

  • Diccionarios de datos
  • Caché de información de usuarios por ID
  • Conteo de frecuencias (ej. cuántas veces aparece una palabra)

Demo Paso a Paso: Registro de Calificaciones 

import java.util.HashMap;
import java.util.Map;

public class SistemaNotas {
    public static void main(String[] args) {
        // 1. Instanciación: Llave (String - Nombre), Valor (Double - Nota)
        Map<String, Double> notasEstudiantes = new HashMap<>();

        // 2. Insertar datos (put)
        notasEstudiantes.put("Santiago", 4.5);
        notasEstudiantes.put("Laura", 5.0);
        notasEstudiantes.put("Carlos", 3.8);

        // 3. Recuperar un valor (get)
        Double notaLaura = notasEstudiantes.get("Laura");
        System.out.println("Nota de Laura: " + notaLaura);

        // 4. Verificar existencia
        if (notasEstudiantes.containsKey("Carlos")) {
            System.out.println("Carlos está registrado.");
        }

        // 5. Borrado
        notasEstudiantes.remove("Carlos");

        // 6. Recorrido de llaves y valores (EntrySet)
        System.out.println("--- Listado de Notas ---");
        for (Map.Entry<String, Double> entrada : notasEstudiantes.entrySet()) {
            System.out.println("Estudiante: " + entrada.getKey() + " | Nota: " + entrada.getValue());
        }
    }
}

💡 Ventaja Principal:

La búsqueda por clave en un HashMap es O(1) en promedio, mientras que en un ArrayList es O(n). Esto hace que los HashMaps sean ideales para consultas frecuentes.

Modularidad - Métodos, Parámetros y Retorno

El Principio de Responsabilidad Única

Un método debe hacer una sola cosa y hacerla bien. Si tu método procesarPago() también imprime la factura y envía un correo, está mal diseñado. La modularidad permite que el código sea testeable y reutilizable.

Teoría Completa y Conceptos Clave

  • 1. Firma del Método: Se compone del nombre y la lista de parámetros. Java permite la Sobrecarga (mismo nombre, diferentes parámetros).
  • 2. Paso por Valor: En Java, todo se pasa por valor. Para primitivos, se pasa una copia del dato. Para objetos, se pasa una copia de la referencia (dirección de memoria).
  • 3. Tipo de Retorno: Define el final del método. Si es void, no devuelve nada. Si tiene un tipo (int, List, etc.), debe usar la palabra reservada return.
  • 4. Modificadores de Acceso: public, private, protected. (En este nivel, nos enfocamos en public para visibilidad total).

Demo Paso a Paso: Procesador de Impuestos 

import java.util.ArrayList;
import java.util.List;

public class ContabilidadApp {
    public static void main(String[] args) {
        double salarioBruto = 3500000;
        
        // Llamado a un método que retorna un valor simple
        double impuesto = calcularIVA(salarioBruto, 0.19);
        System.out.println("Impuesto a pagar: " + impuesto);
        
        // Llamado a un método que procesa colecciones
        List<String> errores = new ArrayList<>();
        validarSalario(salarioBruto, errores);
        
        System.out.println("Errores encontrados: " + errores);
    }

    /**
     * Calcula el valor de un impuesto dado un monto y una tasa.
     * @param monto El valor base.
     * @param tasa Porcentaje en decimal (ej: 0.19).
     * @return El valor del impuesto calculado.
     */
    public static double calcularIVA(double monto, double tasa) {
        return monto * tasa;
    }

    /**
     * Valida si un salario es legal y añade errores a una lista.
     * @param salario Monto a validar.
     * @param listaErrores Lista que se modifica por referencia.
     */
    public static void validarSalario(double salario, List<String> listaErrores) {
        if (salario < 1300000) {
            listaErrores.add("El salario es menor al mínimo legal.");
        }
    }
}

📌 Conceptos en Acción:

  • calcularIVA(): Retorna un valor primitivo (double)
  • validarSalario(): Es void pero modifica una List que se pasa por referencia
  • Reutilización: Ambos métodos pueden llamarse desde cualquier parte del programa

Null Safety (El Cinturón de Seguridad)

Antes de tocar cualquier colección, debemos entender que Java no perdona el acceso a referencias vacías. En Java, una variable de tipo objeto que no ha sido inicializada o que apunta a "nada" tiene el valor null. Intentar acceder a un método o propiedad de algo que es null provocará que el programa "explote" (se detenga abruptamente).

¿Qué es el NullPointerException (NPE)?

Es un error de tiempo de ejecución que ocurre cuando la Máquina Virtual de Java (JVM) intenta realizar una operación sobre una referencia que no apunta a ningún objeto en memoria. Es como intentar abrir una puerta con una llave que no existe.

El peligro en las Colecciones

Las colecciones son "puntos calientes" para este error por dos razones principales:

  • En ArrayList: Si intentas obtener un objeto de una lista que contiene un null y luego llamas a un método sobre él.
  • En HashMap: Si pides una llave que no existe, el método .get(key) te devolverá null. Si intentas usar ese resultado sin validar, el programa fallará.

Teoría de Seguridad

  • Definición de null: Representa la ausencia de valor en una referencia de objeto.
  • El NPE (NullPointerException): Es el error que ocurre al intentar usar un objeto que es null.
  • Estrategia: Siempre debemos preguntar if (objeto != null) antes de invocar métodos.

Antes de operar con cualquier objeto que provenga de una fuente externa o una colección, debemos aplicar un filtro de seguridad. 

Map<String, Double> precios = new HashMap<>();
// ... supongamos que el mapa está vacío

Double precio = precios.get("Laptop"); // Esto devuelve null

// ❌ ERROR SEGURO:
// double total = precio * 1.19; // Esto lanza NullPointerException

// ✅ FORMA SEGURA:
if (precio != null) {
    double total = precio * 1.19;
    System.out.println("El total es: " + total);
} else {
    System.out.println("Error: El producto no existe.");
}

Técnicas Modernas de Prevención

getOrDefault()

En lugar de recibir un null, puedes pedirle al mapa que te devuelva un valor base si la llave no existe. 

Double precio = precios.getOrDefault("Laptop", 0.0);
containsKey()

Verificar la existencia antes de extraer.

Optional (Nivel Avanzado)

Un contenedor que indica explícitamente si un valor está presente o no.

❓ ¿Por qué Java permite el valor null si es tan peligroso?

null es útil para representar la ausencia de un valor. El problema no es el null en sí, sino el programador que olvida validar su existencia antes de usarlo.

❓ ¿Es lo mismo una lista vacía que una lista null?

No. Una lista vacía es un objeto real (una caja vacía). Una lista null es la ausencia total del objeto (ni siquiera tienes la caja).

Práctica Acompañada: Sistema de Gestión de Talento

Escenario

Vamos a crear un programa que gestione una lista de empleados y sus salarios, integrando ArrayList para mantener el orden, HashMap para acceso rápido, y métodos modulares para la lógica.

Paso a Paso

  1. Estructura Base: Crea una clase llamada GestionTalento
  2. El Almacén: Crea un ArrayList para los nombres de empleados y un HashMap para asociar nombres con salarios.
  3. El Módulo de Registro: Crea un método registrarEmpleado que guarde en ambos contenedores y sea void.
  4. El Módulo de Consulta: Crea un método obtenerSalario que devuelva el salario (double).

La Solución 

import java.util.*;

public class GestionTalento {
    // Declaramos las estructuras como estáticas
    static List<String> listaNombres = new ArrayList<>();
    static Map<String, Double> mapaSalarios = new HashMap<>();

    public static void main(String[] args) {
        // Ejecución de la lógica
        registrarEmpleado("Ana", 2500.0);
        registrarEmpleado("Pedro", 1800.0);
        
        System.out.println("Nombres registrados: " + listaNombres);
        System.out.println("Salario de Ana: $" + obtenerSalario("Ana"));
    }

    // Método modular para registro
    public static void registrarEmpleado(String nombre, double salario) {
        listaNombres.add(nombre);
        mapaSalarios.put(nombre, salario);
        System.out.println("Sistema: " + nombre + " registrado exitosamente.");
    }

    // Método modular para consulta
    public static double obtenerSalario(String nombre) {
        if (mapaSalarios.containsKey(nombre)) {
            return mapaSalarios.get(nombre);
        }
        return 0.0; // Retorno por defecto si no existe
    }
}

Conceptos Integrados:

  • ArrayList: listaNombres mantiene el orden de registro
  • HashMap: mapaSalarios proporciona búsqueda O(1)
  • Métodos: registrarEmpleado() y obtenerSalario() son modulares y reutilizables
  • Null Safety: containsKey() valida antes de acceder

Ejercicio Independiente: Sistema de Turnos de un Banco

Objetivo del Ejercicio

Eres el desarrollador de un banco. Debes crear un programa que gestione la fila de espera de clientes usando ArrayList, un registro de transacciones con HashMap, y un método modular para atender clientes.

Instrucciones

  1. ArrayList para la fila: Usa un ArrayList para gestionar la fila de espera de clientes (los clientes entran y salen en orden).
  2. HashMap para transacciones: Registra cuántas transacciones ha hecho cada cliente en el día (Llave: nombre, Valor: cantidad de transacciones).
  3. Método atenderSiguiente(): Debe:
    • Tomar al primer cliente de la lista
    • Sumarle 1 a su contador de transacciones en el mapa
    • Eliminarlo de la fila de espera
    • Mostrar: "Atendiendo a [Nombre]. Transacciones totales hoy: [Cantidad]"

Criterios de Logro

  • Eliminar correctamente el elemento en el índice 0 del ArrayList
  • Verificar si el cliente ya existe en el Map antes de sumar (si no existe, su primera transacción es 1)
  • Uso correcto de métodos con parámetros adecuados
  • Validación de null safety: verificar si la fila no está vacía antes de atender

¿Qué Más Debería Saber?

Estos conceptos avanzados te prepararán para escribir código Java profesional y evitar errores comunes en producción.

La Trampa del for-each y la Eliminación

Nunca elimines un elemento de un ArrayList mientras lo recorres con un for-each básico; Java lanzará una ConcurrentModificationException.

❌ Incorrecto:

for (String cliente : filaClientes) {
    filaClientes.remove(cliente); // ¡Error!
}

✅ Correcto (Opción 1 - Iterator):

Iterator<String> it = filaClientes.iterator();
while (it.hasNext()) {
    it.next();
    it.remove(); // Seguro
}

✅ Correcto (Opción 2 - Inverso):

for (int i = filaClientes.size() - 1; i >= 0; i--) {
    filaClientes.remove(i); // Desde el final
}

Programar para la Interfaz, No la Implementación

Nota que en los ejemplos usamos List<String> lista = new ArrayList<>();. Esto es una buena práctica profesional que te da flexibilidad total.

Ventaja Principal:

Si mañana descubres que ArrayList es lento y necesitas LinkedList, solo cambias la parte derecha del operador de asignación. El resto del código no cambia.

Antes (Acoplado):

ArrayList<String> lista = new ArrayList<>();
// Muí acoplado a ArrayList

Después (Flexible):

List<String> lista = new ArrayList<>();
// Fácil cambiar por LinkedList

Regla de Oro

Siempre que posible, usa la interfaz (List, Map, Set) en la declaración y la implementación específica (ArrayList, HashMap, HashSet) solo en el lado derecho del new. Esto es un pilar del design pattern Strategy y del principio SOLID de inversión de dependencias.
