Unidad I: Fundamentos y Modularidad

📌 Recuerda

  • Java es Fuertemente Tipado: No podemos guardar un String donde definimos un Integer.
  • Referencia vs. Valor: Las colecciones guardan referencias a objetos, no los objetos en sí.
  • Git no es un respaldo, es un historial: Cada commit debe representar una unidad funcional lógica de código.

El Concepto Técnico: Static

En Java, cuando declaras una variable como static, le estás diciendo a la Máquina Virtual de Java (JVM) que esa variable pertenece a la Clase y no a los objetos individuales que creas a partir de ella.

❌ Sin static (Instancia)

Cada vez que creas un objeto (un "restaurante" nuevo), este tendría su propia lista de pendientes vacía.

Ejemplo:

Si tienes 10 restaurantes, tienes 10 listas independientes e innecesarias en memoria.

✅ Con static (Clase)

Solo existe una única lista en toda la memoria del programa para todos los objetos de esa clase.

Ejemplo:

Es una "variable global" dentro del contexto de esa clase. Eficiente y compartida.

💡 Cuándo Usar Static:

Usa static cuando quieras que todos los objetos de una clase compartan el mismo valor (contadores, configuraciones globales, métodos de utilidad). Usa variables de instancia cuando cada objeto necesite sus propios valores.

Modularidad Avanzada y Operaciones List

El Contrato de los Métodos

Un método profesional no solo ejecuta; valida. Antes de realizar una operación sobre una List, debemos asegurar que los parámetros sean consistentes para evitar el temido NullPointerException.

Caso de Uso: El "Checklist" de Tareas Automático

Un sistema que permite agregar tareas, pero que las limpia automáticamente si detecta duplicados.

Implementación Paso a Paso:
  1. Definición: Creamos una List<String> para el almacenamiento.
  2. Modularización: Un método exclusivo para la lógica de inserción segura.
  3. Lógica: Usar el método .contains() antes de .add().

Implementación Completa 

import java.util.*;

public class SistemaTareas {
    // Estructura dinámica que crece según la necesidad 
    static List<String> pendientes = new ArrayList<>();

    public static void main(String[] args) {
        // Simulación de flujo de trabajo
        registrarTarea("Configurar GIT");
        registrarTarea("Crear ArrayList");
        registrarTarea("Configurar GIT"); // Intento de duplicado
        
        System.out.println("Tareas finales: " + pendientes);
    }

    // Modularidad: Responsabilidad única de validación y registro
    public static void registrarTarea(String tarea) {
        if (tarea != null && !pendientes.contains(tarea)) {
            pendientes.add(tarea);
            System.out.println("Tarea agregada: " + tarea);
        } else {
            System.out.println("Error: Tarea nula o ya existente.");
        }
    }
}

✅ Validaciones en Acción:

  • tarea != null - Previene NullPointerException
  • !pendientes.contains(tarea) - Evita duplicados
  • La lógica de inserción es responsable única en un método dedicado
  • El retorno es void pero el método produce efectos secundarios útiles (agregar o rechazar)

Estructuras Map y Casos de Uso Real

La Eficiencia del Hash

Mientras que en una List buscar un elemento implica recorrerla (lento), en un Map la búsqueda es instantánea (O(1)) mediante el uso de llaves únicas.

Comparación:

ArrayList.get() = O(1) acceso directo

ArrayList búsqueda lineal = O(n) recorrer todo

HashMap.get() = O(1) búsqueda por clave

Caso de Uso: Sistema de Autenticación de Usuarios (Simulado)

En el Back End, los usuarios se buscan por su correo electrónico o ID. Usaremos un Map para simular una base de datos en memoria.

🗝️ Estructura del Map:

Key: Email (Único) | Value: Rol de usuario

Implementación Completa 

import java.util.*;

public class AuthSystem {
    // Key: Email (Único), Value: Rol de usuario 
    static Map<String, String> baseDatos = new HashMap<>();

    public static void main(String[] args) {
        // Poblado inicial
        baseDatos.put("santiago@cesde.edu", "Admin"); 
        baseDatos.put("estudiante@cesde.edu", "User");

        // Caso de uso: Login
        verificarAcceso("santiago@cesde.edu");
        verificarAcceso("desconocido@web.com");
    }

    public static void verificarAcceso(String email) {
        // Uso de Null Safety al recuperar del mapa 
        String rol = baseDatos.get(email); 

        if (rol != null) {
            System.out.println("Bienvenido. Su rol es: " + rol);
        } else {
            System.out.println("Acceso denegado: Usuario no encontrado.");
        }
    }
}

💡 Conceptos Integrados:

  • Static Map: baseDatos simula una base de datos en memoria compartida
  • Búsqueda O(1): El método .get() es instantáneo sin importar el tamaño del Map
  • Null Safety: Se valida si rol != null antes de usarlo
  • Modularidad: La lógica de verificación está en un método dedicado verificarAcceso()
  • Caso Real: Este patrón se usa en sistematización de autenticación profesional (con bases de datos reales)

📦 Integración con GIT

En un entorno real, el código no vive solo en el editor. Debemos aprender a versionar estos ejercicios usando GIT como sistema de control de versiones.

Flujo Práctico en Consola

git init

Crea la estación de control de versiones en tu proyecto.

git status

Ver qué "documentos" o cambios hay en la carpeta sin rastrear.

git add .

Poner todos los cambios en la estación de preparación (staging).

git commit -m "feat: implementar sistema de login con HashMap"

Confirmar los cambios con un mensaje descriptivo (Conventional Commits).

Conventional Commits

Un commit profesional se estructura así: <prefijo>: <descripción en minúsculas>.

Prefijo ¿Cuándo usarlo? Ejemplo
feat Nueva funcionalidad feat: agregar validación de email
fix Corrección de bugsreparación de errores fix: resolver NullPointerException
docs Cambios en documentación docs: actualizar README.md
style Formato sin lógica (espacios, indentación) style: formatear código con espacios
refactor Reorganización sin cambiar funcionalidad refactor: simplificar lógica de validación
test Pruebas unitarias test: agregar pruebas para AuthSystem
chore Tareas rutinarias y mantenimiento chore: actualizar dependencias

Importancia del .gitignore

Nunca hagas commit de archivos temporales de tu IDE (como la carpeta .idea o .settings). Usa siempre un archivo .gitignore.

✅ Si el archivo es nuevo

(Aún no has hecho git add)

  1. Crear el archivo .gitignore en la raíz
  2. Escribir las rutas a ignorar
  3. Guardar y hacer commit

Ejemplo de contenido:

.idea/
.settings/
*.class
__pycache__/
❌ Si el archivo ya fue subido

(El error común)

  1. Quitar del índice: git rm -r --cached .idea/
  2. Añadir al .gitignore
  3. Commit: git commit -m "chore: eliminar IDE config"

Ejercicios: Poniendo Todo en Práctica

Demo Acompañada: El Gestor de Inventario con Alertas

Debes construir un programa que combine todo lo visto hasta ahora: HashMap, métodos modulares, validaciones y lógica condicional.

Instrucciones
  1. Estructura: Usa un HashMap<String, Integer> donde la llave es el nombre del producto y el valor es el stock.
  2. Método Modular: Crea actualizarStock(String producto, int cantidad)
  3. Lógica de Alerta: Si el stock llega a menos de 5 unidades, el método debe imprimir una alerta de "⚠️ Stock Crítico" además de actualizar el valor.
  4. Control de Versiones: Al finalizar, realiza un commit con mensaje feat: implementar gestor de inventario con alertas

💡Pistas de Implementación:

  • Usa put() para insertar/actualizar productos
  • Usa getOrDefault() para manejar el caso si el producto no existe
  • Implementa validación: ¿qué pasa si la cantidad a restar es mayor que el stock?
  • Considera hacer static el HashMap para compartirlo entre métodos

Ejercicio Independiente: Sistema de Turnos Bancarios

Integra List, métodos modulares, validaciones de seguridad y GIT. Este es el desafío que consolida tu aprendizaje.

Instrucciones
  1. Estructura de Datos: Crea una List<String> para los nombres de los clientes en espera.
  2. Método Modular atenderSiguiente():
    • Valide si la lista está vacía utilizando isEmpty() o size() == 0
    • Extraiga el primer cliente (index 0) y elimínelo de la lista
    • Retorne el nombre del cliente atendido (tipo de retorno: String)
  3. Manejo de Errores: Si la lista está vacía, retorna null o un mensaje como "NO_HAY_CLIENTES"
  4. Control de Versiones: Sube tu solución a un repositorio de GitHub y comparte el enlace en el aula.

Criterios de Evaluación:

  • ✅ Validación correcta de lista vacía (Null/Empty Safety)
  • ✅ Extracción correcta del index 0 y eliminación
  • ✅ Tipo de retorno apropiado (String)
  • ✅ Modularidad: lógica en un método dedicado
  • ✅ Repositorio de GitHub con commits usando Conventional Commits
  • ✅ Archivo .gitignore configurado correctamente

¿Debería Saber Algo Más?

Sugerencia Crítica: Más Allá de Static

En Java profesional, no usamos static para todo. Estamos usándolo aquí para facilitar la ejecución en el main, pero la verdadera potencia viene de crear objetos (instancias).

Git - Sugerencia Profesional

Existe un sitio web llamado gitignore.io donde escribes "Java" o "IntelliJ" y te genera automáticamente el archivo .gitignore completo.

💪 Ventaja:

Es una herramienta profesional que te ahorra mucho tiempo y asegura que no commits archivos innecesarios. Simplemente copia el contenido generado y pégalo en tu .gitignore.

Ejemplo de flujo:

1. Visita gitignore.io → Escribe "Java" → Copia resultado → Pega en .gitignore → git add . → git commit
